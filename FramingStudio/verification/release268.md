# E2.268 — Equal bar counts in automatic beam layers

Baseline E2.267 / 8121fd9087d0f15ea3f9aadd9c7069ac7c06ea17. Official main b07f04a6ca4fe84940a8071f316aae85e3a688d0, release v2.256 and PR 10/11 heads were checked before editing and again before publication; no intervening remote update was found.

Automatic MB/SB/TB/CB reinforcement now uses the first occupied layer's bar count on every occupied layer of the same face, for both compression and tension reinforcement (including the reversed physical faces of a cantilever). The former partially filled final layer is rounded up to a full layer. Unused layers stay empty. Manual layer counts remain independent and are not rewritten.

Candidate selection still applies the original section fit, clear spacing, maximum eight layers, per-face 4% area limit, link policy and shared Check acceptance. The rounded full-layer area is checked before adopting the candidate. When that area exceeds the existing limit, the failure states the face, bar arrangement, area and limit. Existing failed-Check gates prevent both A and B export; failed trial steel is not adopted by Excel. No section, load or material input is changed to force a pass.

Current saved model verification: 1/F SB19 (250 x 400) and 2/F SB19 (250 x 450) cannot adopt two layers of 2T40: 5,026.5 mm2 exceeds their existing 4,000 / 4,500 mm2 limits. They are reported as failed automatic selection and excluded from verified reports. No manual override was inserted. The other eight selected members pass App RC selection; 2/F CB_3 changes from 15+1 to 15+15 T40 on its tension face, with d recalculated from 615 to 580 mm. All results are recalculated using the unchanged equations. Original Excel L/d status text remains as computed; shared acceptance still allows the existing alternative deflection route.

Validation:

- 108 automatic cases across four beam types, multiple widths/depths/moments: 92 pass, 16 explicitly fail. Successful multilayer faces have equal counts; rounded areas remain within the original limit. Identical manual inputs give identical complete results to E2.267, including explicit unequal 2+1 layers on both faces.
- Existing link-policy267 (36 automatic / 72 manual cases), rebar-live237, rebar227 DOM editing/save/AUTO restoration, and section-a-acceptance262 checks pass. The latter now explicitly verifies failed-Check rejection for both A and B.
- Fresh native Excel baseline and updated combined Check runs use the same eight eligible members and identical load/input tables. Each completes 2,032 App/Excel comparisons with zero differences; A and B copies are generated by the original native routines.
- 17,953 original workbook formula strings, both A/B report styles, row heights, column widths, merged cells, print areas/settings and page breaks agree with the same-member baseline. Twenty-three exported PDF pages retain the same page counts and paper dimensions. Changed CB A/B pages were visually inspected.
- Eight independent Section B member calculation sheets retain formula coordinates and private input references; 960 input/result cells verified. Mixed-member load formulas and native M/V/reactions remain intact.
- The Excel template, VBA, extracted formula definitions, ExcelBridge source/binary and report renderers are byte-for-byte unchanged from E2.267. Only automatic candidate selection, its failure explanation, version metadata and regression tests changed.

The existing preview at port 8783 is reused without changing browser/project storage or forcing a reload. This release does not alter the original Excel workbook's standalone VBA auto-design buttons or claim to fix the previously observed intermittent Excel process interruption.
